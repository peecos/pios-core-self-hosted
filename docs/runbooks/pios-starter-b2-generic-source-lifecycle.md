# PIOS Starter B2: Generic Source Lifecycle And Receipt Contract

## Scope

`scripts/pios_generic_source_lifecycle.py` is a zero-network, local synthetic
library layered on B1. It provides candidate validation, immutable receipt
binding, accepted/duplicate/denied/retry/revoked/export result shapes, and
independent original-byte readback.

The `owner_id` field is a generic receipt-binding input, not an owner chosen or
configured by the Starter. Tests use only `owner_synthetic_b2` and harmless
generated bytes. No owner, device, app, provider, endpoint, credential, or
service is embedded in the image.

## Candidate And Receipt Bindings

A candidate binds:

- generic owner ID and integration ID;
- opaque stable source record ID and payload-bound idempotency key from B1;
- canonical candidate payload integrity;
- original byte SHA-256 and byte count;
- canonical processing-manifest SHA-256 and byte count;
- unknown extensions; and
- logical-reference/provenance separation from B1.

An accepted receipt includes those identity and integrity bindings plus only
canonical logical references:

```text
core://events/<receipt-id>
core://originals/<original-sha256>
core://system/processing-manifests/<manifest-sha256>
```

Duplicate responses return the same verified receipt. A changed candidate under
the same stable source identity returns `source_identity_conflict`. A receipt
with any changed binding fails verification.

## Boundaries

- `LocalSyntheticSourceLifecycle` is a temporary-directory test harness, not
  an adapter or server.
- Synthetic decision controls are function arguments for local tests; they are
  not candidate fields, device grants, or real authorization.
- B2 does not implement a Corebox, Ally/History, Dash, or other source
  adapter; it does not open a listener or make a network call.
- The current r3 image artifact is unchanged. The module is included only in
  future image-root builds and therefore a later capability-bearing image must
  re-run existing hygiene/residue/recovery evidence.
