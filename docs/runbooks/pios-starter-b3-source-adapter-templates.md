# PIOS Starter B3: Generic Source Adapter Templates

## Purpose

This runbook verifies the owner-neutral B3 adapter-template capability carried
by a future PIOS Starter Disk Image. It builds only harmless generated local
fixtures. It does not read an application folder, accept an actual update
body, connect to a provider, or configure a network service.

The implementation is `scripts/pios_source_adapter_templates.py`. It composes
the B1 canonical source primitives and the B2 local lifecycle/receipt contract
without changing either contract.

## Template Families

`OriginalByteCaptureTemplate` represents an item whose immutable original is a
generated byte sequence. `StructuredEvidenceTemplate` represents a generated
structured-evidence record whose immutable original is canonical JSON bytes.

Both templates:

- use only `owner_synthetic_b3`, a fixed synthetic receipt-binding value;
- produce a B2 candidate and validate its evidence, original digest, byte
  count, and manifest binding before returning it;
- preserve caller-supplied unknown extension objects unchanged through the B1
  canonicalization boundary; and
- use opaque generated record identifiers supplied by a local test only.

Neither template contains an application binary, source-folder path, endpoint,
credential, user configuration, notification, or actual owner content.

## Local Harness Contract

`LocalSyntheticAdapterHarness` provides local outbox and receipt-ledger
semantics:

1. `enqueue()` verifies the prepared candidate and creates immutable outbox
   metadata plus immutable original bytes under its temporary local root.
2. `submit_enqueued()` re-verifies those bytes, calls B2's
   `LocalSyntheticSourceLifecycle`, and only records an accepted or duplicate
   receipt after B2 receipt verification succeeds.
3. The receipt-ledger entry binds its template name and candidate digest to the
   exact B2 receipt. A conflicting second write fails closed.

The harness has no transport code. Its root is supplied by the caller; tests
use an automatically cleaned temporary directory. It is evidence machinery,
not a service or persistent source connector.

## Verification

Run from the repository root:

```sh
python3 -m unittest tests/test_pios_source_adapter_templates.py
python3 -m unittest discover -s tests
python3 scripts/build_self_hosted_image_root.py \
  --output-dir /private/tmp/pios-starter-b3-image-root --run-hygiene
python3 scripts/validate_self_hosted_image_root.py \
  --image-root /private/tmp/pios-starter-b3-image-root
```

The focused test proves both template shapes create harmless candidates, retain
unknown extensions, conform to B2, create an idempotent local outbox and
receipt ledger, and fail closed if retained original bytes no longer match
their digest.

Remove the temporary verification directory after inspection. Do not treat it
as an image artifact or a deployment input.

## Boundary

B3 does not authorize a source-specific adapter, live ingestion, an account,
owner binding, public or private ingress, app networking, cloud resources, or
personal data. The next backlog item, B4, may consume verified B2 receipts but
must keep projections and approvals separate from source truth.
